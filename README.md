

# VM - стековая виртуальная машина"

Целью данного проекта была попытка разобраться в устройстве виртуальных машин, способных исполнять некоторый байт код. Проект состоит из 2-х частей:
- Транслятор собственного ассемблера в байт код
- Виртуальная машина, исполняющая байт код

Реализованная виртуальная машина относится к стековому типу, загрузка операндов большинства опкодов производится непосредственно через стек, однако архитектура оставляет возможность перехода к классической регистровой организации.

## Зависимости
Для стандартной сборки потребуется
- Make
- GCC/G++/Clang (дефолтный Makefile использует G++ лишь для поддержки некоторых флагов)

## Сборка
| Команда | Описание |
|---------|----------|
| `make vm` | Сборка виртуальной машины |
| `make translate` | Сборка транслятора ассемблера |
| `make all` | Сборка всех компонентов |
| `make rebuild` | Очистка и пересборка всего |
| `make clean` | Очистка всего |
| `make agen` | Сборка генератора кода, для автоматической загрузки ASCII анимации |

ВАЖНО: Стандартный Makefile использует powershell команды для рекурсивного сбора исходников, из-за чего он OS dependent.

# Использование
При наличии не константных операндов, они складываются на стек слева-направо, результат также кладется на стек
| Опкод | Инструкция | Имеет операнды | Описание | Пример |
|-------|------------|----------------|----------|--------|
| `0X00` | `HALT` | - | Остановка ВМ | `HALT` |
| `0X10` | `ADD` | + | Сложение двух чисел | `ADD` |
| `0X11` | `SUB` | + | Вычитание двух чисел | `SUB` |
| `0X12` | `MUL` | + | Умножение двух чисел | `MUL` |
| `0X13` | `DIV` | + | Деление двух чисел | `DIV` |
| `0X0F` | `СMP` | + | Сравнение двух чисел, выставляет флаги сравнения | `CMP`|
| `0X06` | `JMP` | - | Безусловный прыжок на метку | `JMP label` |
| `0X08` | `JZ` | - | Прыжок на метку, если ZF | `JZ label` |
| `0X07` | `JNZ` | - | Прыжок на метку, если !ZF | `JNZ label` |
| `0X09` | `JL` | - | Прыжок на метку, если !ZF && CF | `JL label` |
| `0X0A` | `JLE` | - | Прыжок на метку, если ZF || CF | `JLE label` |
| `0X0C` | `JG` | - | Прыжок на метку, если !ZF && !CF | `JG label` |
| `0X0B` | `JGE` | - | Прыжок на метку, если ZF || !CF | `JGE label` |
| `0X0D` | `CALL` | - | Вызов процедуры (положить на стек адрес возврата и прыгнуть на метку) | `CALL proc` |
| `0X0E` | `RET` | - | Прыжок по адресу возврата | `RET` |
| `0X05` | `MOV` | - | Снять значение с вершины стека, скопировать его в регистр/память по адресу/память по оффсету относительно регистра | `MOV reg/[imm64]/[reg+-imm64]` |
| `0X04` | `PUSH` | - | Скопировать значение из указанного регистра на стек | `PUSH` |
| `0X03` | `POP` | - | Снять значение с вершины стека (значение просто пропадет) | `POP` |
| `0X01` | `IN` | - | Пользовательский ввод, значение попадет на стек | `IN` |
| `0X02` | `OUT` | - | Вывести вершину стека | `OUT` |
| `0X15` | `DRAW` | - | Вывод содержимого ОЗУ в консоль в виде набора ASCII символов | `DRAW` |
| `0X14` | `DMP` | - | Дамп виртуальной машины | `DMP` |

## Трансляция и исполнение
* Для трансляции ассебмлера в байт код: \
`translate.exe <input file> <output file>`\
* После того как вы получили бинарник (или ошибку). Вызовите виртуальную машину:\
`vm.exe <input file>`

### Добавление собственных инструкций
Для того, чтобы добавить собственную инструкцию `NAME` необходимо:
* Выбрать свободный опкод для инструкции, добавить его в `src/defines/arch.h`
* Создать реализацию для её парсинга транслятором (объявление должно совпадать: `void handleNAME  (Buffer* READ_BUFFER, Buffer* WRITE_BUFFER);`) или использовать макрос `HANDLE_SIMPLE` из `src/translator/src/instructions/instructions.c`. Объявление функции парсинга необходимо разместить в `src/translator/src/instructions/instructions.h`
* Создать реализацию для её исполнения виртуальной машиной (объявление должно совпадать: `void opNAME  (VM* vm);`). Объявление функции исполнения необходимо разместить в `src/vm/src/operations/operations.h`
* Связать вышеперечисленные функции в `src/structures/descriptions.c`, добавив в `void descriptionsInit ()` ещё одну строку вида `ADDDESCRIPTION (NAME)`

При этом при парсинге вы работаете с двумя строковыми буфферами, интерфейс структуры `Buffer` лежит в `src/included/buffer/buffer.h`. В случае же написании исполняющей функции для виртуальной машины, вы получаете на вход `VM*` - указатель на структуру, описывающую состояние виртуальной машины, рекомендую ознакомиться с `src/vm/src/vm.h`

За примерами реализаций вышеуказанных функции рекомендуется обратиться в исходный код. Интерфейс получился очень гибким и не ограничевает практически ни в чём, так за основу был взят формат инструкций `x86_64` с переменной длиной. К примеру инструкция `MOV` практически полностью повторяет формат упаковки операндов
